2a. The batched version converges to about 190 FPS, while the sprite-by-sprite version converges to about 125 FPS on the same machine with the same scene. The difference is the cost of submitting 10,000 separate draw calls every frame; batching combines all of them into one, so the CPU stops spending a large part of each frame just handing work to the GPU. What remains is the per-frame particle update, which both versions do identically.

2b. Give every sprite a depth value and let the rasterizer resolve the ordering: enable the depth test, write each quad's depth into its clip-space z, and fragments behind closer ones are rejected automatically. Then the sprites don't have to be drawn back to front, so the only extra work is storing a depth per sprite and turning the test on.
